## 联动实测九项逐条结论

| 序号 | 联动检查项 | 实测具体结论 | 机制说明与边界 |
| :---: | :--- | :--- | :--- |
| **1** | **从文档拖拽内容进入插件是否正常** | **受限支持（文本支持 / 块未支持）** | 拖入原生输入框可接收纯文本；但拖拽带有思源内部数据类型的块到插件卡片/向导无专用 dropzone 监听（已录入候选需求 `IDEA-02`）。 |
| **2** | **插件结果能否写回文档、块或块属性，写回后格式是否被破坏** | **完全正常** | 写入日记列表、人物事实段、组织 Markdown 表格及 `custom-lvct-*` 受控属性均通过事务 API；正文无裸露大括号代码，格式与排版完整。 |
| **3** | **通过块标识跳转时能否正确定位并滚动到位** | **完全正常** | 已在 Round-2 全面落地：`openSiYuanDocument` 升级支持 `targetBlockId` 及 `highlight` 参数，向思源内核传递 `action: ["cb-get-hl", "cb-get-context"]`，支持跨日记与长文档的块级精准滚动定位与高亮黄色闪烁。 |
| **4** | **生成的引用与反向链接是否正常建立** | **完全正常** | 写入日记时严格采用思源原生块引语法 `((docId '姓名'))`，思源内核解析为 `NodeBlockRef`，在反链面板与 SQL 查询中均建立真实双向链接。 |
| **5** | **编辑器内插入的块能否正常渲染、编辑与再次打开** | **完全正常** | 无论是日记互动列表、组织 Markdown 架构表格还是人物事实块，在思源主编辑器中均可自然渲染并二次编辑；受控块改动具备防冲突校验。 |
| **6** | **文档变化时插件内的展示是否同步更新** | **插件内操作即时同步 / 外部手改受限** | 插件内操作通过 `emitDataChanged` 广播，多面板与浮动档案条即时响应刷新；若在思源编辑器手动打字修改正文，需重新聚焦或切换触发 `switch-protyle` 刷新。 |
| **7** | **同一文档在多窗口或多标签下状态是否一致** | **完全正常** | 通过 `subscribeDataChangedDebounced` 与 `window.dispatchEvent` 全局总线分发，多标签页与多窗口实例均能同步刷新当前状态，无分裂错乱。 |
| **8** | **插件内操作是否进入思源历史记录并可撤销** | **文档版本历史正常 / 编辑器 Ctrl+Z 不可直接撤销** | 通过 API 写入的块会进入思源后端文档快照与 SQLite 日志，支持文档历史版本回滚；但思源编辑器前端的 `Ctrl+Z` 仅记录当前编辑器键盘输入栈，无法直接按键撤销 API 写入。插件端已提供就地修改、删除撤回与墓碑安全机制作为补充。 |
| **9** | **插件生成的内容在导出或分享时是否仍正常** | **完全正常** | 导出的 Markdown 与 PDF 均保持标准列表、表格与文本锚点，无内部代码外溢，排版美观规范。 |
