# 小驴人脉（siyuan-contacts）× 思源笔记原生文档深度联动规划方案

- **制定日期**：2026-10-31
- **基线版本**：`v0.7.4`
- **关联决策**：`D-0001`（一人一文档，数据主权在思源）、`D-0039`（人物原生补充资料）、`D-0040`（主线收敛与未发布自管存储归位文档）
- **核心目标**：彻底消除“插件面板一套数据、打开思源文档却是空的或半截裸代码”的两张皮割裂感，让**所有业务内容都在思源原生文档中有清晰、可读、可双链、可搜索的体现**，同时守住多端同步安全、编辑器光标不跳动、卸载插件后 100% 优雅降级为纯正思源笔记的工程底线。

---

## 一、 现状诊断：为什么当前插件与思源文档像“两张皮”？

对照 `v0.7.4` 生产代码与真实思源内核实测，当前文档联动存在 **5 个核心断层**：

1. **大量人物与组织信息仍锁在插件私有 JSON 黑盒，打开思源文档完全看不见**
   - **人物侧未上墙项**：`初识场合与引荐人`（`person-origins.json`）、`人物别名`（`person-aliases.json`）、`下次待聊谈资`（`person-topics.json`）、`礼物点子`（`gift-ideas.json`）、`双向约定`（`person-promises.json`）、`拜访行程`（`person-itineraries.json`）、`家庭亲属`（`person-kinship.json`）、`协作项目`（`person-projects.json`）、`闪念便签`（`person-scratchpads.json`）均未体现在人物文档正文中。
   - **组织侧几乎空白**：`organization-profiles.json` 中的组织简称、简介、企查查链接、**部门架构树**与自定义字段全部只存在插件 JSON 中；打开思源里的组织文档，只能看到一行当前成员列表，连公司介绍、部门结构与历史离职成员（前同事/校友）都没有。

2. **未能利用思源原生文档属性与块引用双链，浪费了思源最强的搜索与图谱底座**
   - **别名未写思源原生 `alias` 属性**：别名只存在 `person-aliases.json`，未同步至人物文档块的思源原生 `alias` 属性（`/api/attr/setBlockAttrs`），导致用户在思源里按 `Ctrl+P` 全局搜索或在正文中输入 `((` 敲昵称/英文名时，根本搜不到该联系人文档。
   - **引荐人、亲属、协作项目未生成真实双链**：引荐人 `introducedByDocId`、亲属 `linkedDocId`、协作项目 `relatedDocId` 只在插件内部画图，没有在人物文档里写成 `((targetDocId '名称'))` 块引用，导致思源原生的**反向链接面板**与**原生局部关系图**看不到这些关键连接。

3. **已进文档的区块存在“可读性灾难”与“双轨重复”**
   - **补充资料在文档正文裸露 JSON 代码**：`custom-lvct-person-fields` 目前在人物文档里直接渲染为 `补充资料：{"schemaVersion":1,"ownerDocId":"...","items":[...]}` 一长串代码，既破坏笔记阅读美感，用户一旦不小心改错一个引号就会触发解析报错。
   - **跟进待办双轨重复落盘**：`followup-sync.ts` 会在文档里插入可勾选的原生任务块（`custom-lvct-followup`），而 `doc-section.ts` 在“同步档案到正文”时又会额外生成一块静态的 `## 待办跟进` 超级块（`custom-lvct-followups`），导致同一条待办在文档里重复出现两遍。
   - **依赖手动点击“同步档案到正文”**：在名册、编辑弹窗或详情里修改了电话、分组、关系称谓、纪念日、人情账本后，文档里的 `## 人脉基本档案` 等区块不会全部自动更新，除非用户去点折叠菜单里的「同步档案到正文」，日常极易过期失真。

4. **日记（Daily Note）联动只有“单向盲追加”，改删不同步**
   - 记互动同步到今日日记时只是裸追加一行 Markdown，没有写入稳定事件块属性（如 `custom-lvct-event-id`）。当用户在插件里**就地修改了记错的互动备注或删除了互动**时，当日日记里依然留着修改前的错误文字；且如果重复触发同步缺少块级幂等锚点。

5. **用户自由笔记与插件受控块缺少清晰的版面分区**
   - 若多个受控区块无序插入，会把用户自己在人物文档里写的访谈手记、贴的名片照片切割得支离破碎，用户也不清楚哪一段可以直接改、哪一段改了会被插件下次刷新覆盖。

## 二、 核心架构原则：三层数据主权与联动模型（防打架、防死循环）

要把“所有内容都在思源文档中有体现”做扎实，**绝不能搞成“全靠脆弱的自由文本正则硬猜”**（否则用户改个排版或换个行就会把金额、农历、关联 ID 解析坏），也**不能搞成“只存 JSON 不管文档”**。

所有数据按交互性质严格划分为以下 **三层联动模型**：

### 第一层：思源原生即唯一事实源（Native-as-SoT，零插件 JSON 冗余）
1. **核心 9 字段与显式相关人** $\rightarrow$ **思源原生属性视图数据库（`联系人总表` AV）**
   - 用户在思源原生数据库表格里改电话、改分组、贴标签、连相关人，插件打开即刻生效；插件内修改也直接写 AV 单元格并回读核实。
2. **人物别名 / 曾用名 / 英文名** $\rightarrow$ **人物文档原生 `alias` 块属性 + 档案头展示**
   - 插件维护别名时同步写入人物文档根块的原生 `alias` 属性（逗号分隔），立刻激活思源全局 `Ctrl+P` 别名搜索、`((` 别名引用补全与虚拟引用识别（插件仅保留轻量唯一性冲突校验或直接以文档属性为准）。
3. **人物文档直存型记忆（文档受控块即唯一事实源，插件不另存 JSON）**
   - **自由正文区**：完全归用户所有，插件零写入、零改排。
   - **记住的事（`custom-lvct-facts`）**：承载喜好、忌口红线（`🚫`）、观点金句、背景经历、**下次待聊谈资**与**随手便签**。采用人类可读的标准列表格式（`- 🚫 [忌口红线] 2026-10-31：花生严重过敏`），用户在插件或文档内均可直观阅读，按行格式手改也可无损解析回读。
   - **补充资料（`custom-lvct-person-fields`）**：承载第 2~N 个电话/邮箱、家庭/公司地址、证件号、社交媒体等分组键值。**废除正文裸 JSON 文本**，升级为人类可读的两层 Markdown 列表（带轻量隐藏条目注释或属性保真），打开文档就像看一张整洁的个人资料卡。
   - **个人长备注（`custom-lvct-person-note`）**：承载人物总体评价与背景长文。

### 第二层：原生块双向协同层（Bi-directional Native Blocks，两边都能改）
1. **待办跟进、双向约定与拜访安排** $\leftrightarrow$ **思源原生任务列表块（`- [ ] 📅YYYY-MM-DD ...`）**
   - **合并唯一出口**：取消 `doc-section.ts` 重复的静态跟进汇总块，人物文档只保留一套带块级 `custom-lvct-followup="<id>"` 属性的原生任务列表。
   - **双向直通**：
     - 插件内新建/改期/完成跟进（含收编后的双向约定 `[我答应]` / `[对方答应]` 与会面行程安排）$\rightarrow$ 实时更新人物文档中的原生任务项（及可选对应日期的 Daily Note 任务项）；
     - 用户在思源编辑器里**直接点击复选框打勾 `[x]`、修改任务文字、修改 `📅日期` 或删掉该任务行** $\rightarrow$ 插件通过既有 `reconcileFollowUpTasksFromDoc` 在打开详情/切换文档/工作台刷新时自动对账回写跟进状态（用户删块标记 `docMissing` 绝不强行复活）。

### 第三层：结构化索引 + 自动实时可读双链投影层（Auto-Projected Markdown Mirror）
- **适用范围**：需要跨全库百人毫秒级聚合计算提醒、净额、图谱路径的跨人/时序数据 —— **互动事件流水**、**初识溯源与引荐人**、**多段组织任职履历**、**重要纪念日**、**人情与礼物往来账本**、**组织百科画像**、**群体活动**。
- **联动机制**：
  1. **告别手动点同步**：上述任何一项在插件中发生增、删、改时，由后台**单文档防抖投影调度器（`DocumentMirrorScheduler`）**自动增量更新对应人物/组织文档底部的受控档案块（800ms 防抖合并，内容未变零 API 调用）。
  2. **100% 思源原生双链化**：凡是指向库内文档的关系，投影 Markdown 一律输出思源原生块引用语法 `((docId '显示名'))`（或 `[显示名](siyuan://blocks/docId)`），让思源原生反链面板、悬停预览浮窗与原生关系图彻底打通：
     - 引荐人：`- **初识与引荐**：2025春季峰会 · 引荐人 ((乙docId '李四'))`
     - 亲属关系：`- **家庭亲属**：配偶 ((配偶docId '王某')) · 子女 小明`
     - 组织履历：`- **组织履历**：((组织docId '远山科技')) · 产品部 · 总监（2023-03 ~ 至今）`
     - 协作项目：`- **协作项目**：((项目笔记docId 'Q4 渠道合作'))（进行中 · 负责人）`
     - 互动来源：`- 2026-10-31 🍽️ 聚餐：敲定合作方案（纪要 ((纪要或日记blockId '2026-10-31 日记'))）`

## 四、 五类思源文档的全景联动闭环

1. **人物文档 $\leftrightarrow$ 工作台**：打开文档顶部悬浮条即可看 30 秒会前速览、复制号码、记一笔互动、改资料；插件内一切改动自动静默刷新文档底部档案区，无需手点同步。
2. **组织文档 $\leftrightarrow$ 人物文档**：修改组织资料（部门树、简介）或增减成员时，同时自动更新组织文档与对应人物文档的双向 `((docId))` 履历链接。
3. **每日日记（Daily Note）$\leftrightarrow$ 互动与待办**：
   - 正向写入携带 `custom-lvct-event-id="<eventId>"` 块属性；当用户在插件内**修改或删除该条互动**时，自动按块属性定位当日日记对应行同步修改文案或移除，杜绝日记残留错字与重复追加。
   - 反向感知：用户在日记或任意笔记里用 `((personDocId '姓名'))` 提到某人，人物顶部档案条与详情「互动」页直接展示“未归档笔记提及”，支持**一键转为正式互动**（自动计入最后联系日期与温度，并以 `block:<blockId>` 幂等防重）。
4. **会议纪要 / 群体活动文档 $\leftrightarrow$ 多人时间线**：新建群体活动时支持“同时在思源创建本次活动纪要文档（或绑定现有会议笔记）”，自动在纪要顶部插入参会人双链名单，并在每位参会人的往来记录中挂上该纪要双链。
5. **联系人总表（原生 AV 数据库）$\leftrightarrow$ 全库**：保留思源原生表格/看板操作体验，与插件名册天然共享同一底层属性视图。

## 五、 多维度风险与工程边界考量（必守底线）

1. **防抢编辑器焦点与防清撤回栈（最高优先级体验红线）**
   - 当检测到某篇人物文档**当前正处于思源活跃编辑器焦点且近 3 秒内有键盘输入（dirty typing）**时，后台自动投影自动推迟到失焦或空闲时执行；
   - 严禁整篇文档替换写入，一律只对内容摘要实际发生变化的单个 `custom-lvct-*` 块调用块级更新；内容无变化时 **0 次内核写入**。
2. **Lute 渲染拆块与交互块分离**
   - 展示型多段区块（名片、记住的事、补充资料、互动账目、组织概览）统一使用 `v0.7.3` 已真机验证的 `{{{row ... }}}` 原子超级块封装，杜绝孤立标题块；
   - 需要用户在思源编辑器内**直接点击打勾**的「待办跟进」区块，保持原生任务列表块结构（`type="l" / "i"`），不包裹只读代码框，保证原生勾选丝滑可用。
3. **多端同步冲突与手改保护**
   - **事实源在文档的区块（`记住的事`、`补充资料`、`个人备注`）**：若思源多端同步产生 2 个同属性受控块，或解析发现用户写入了不符合模板的自由段落，**严禁静默覆盖删除**——保持原块不动，在界面提示用户合并或保留；
   - **投影型区块（`身份名片`、`互动流水`、`组织名录`）**：写入时记录内容哈希属性 `custom-lvct-hash`；若发现当前文档块内容与上次写入哈希不一致（说明用户在编辑器里手改了只读投影块），在浮动档案条温和提示“档案块有手工修改，是否刷新同步”，不粗暴暗中抹掉用户手改文字。
4. **批量操作节流与大文档容量治理**
   - vCard 批量导入或批量修改分组时，文档投影进入后台串行节流队列（每批 5 篇，间隔让出主线程），绝不阻塞 UI 响应或锁死内核 SQLite；
   - 单个联系人的往来互动若超过 20 条，文档内默认展示最近 20 条高频记录并注明总条数（支持一键导出完整编年史独立子文档），防止交往数百次后单篇人物文档超级块过大拖慢 Protyle 打开速度。
5. **与 `D-0040` 存储瘦身合流及存量零丢失升级**
   - 不走“再造一堆新 JSON”的老路，借本规划将 `D-0040` 列出的未公开发布碎片 JSON（`person-origins`、`person-social-preferences`、`person-scratchpads`、`person-promises`、`person-itineraries`、`person-kinship`、`person-lifecycle-stage`）分批合并落入人物文档受控块或既有核心结构；
   - 存量数据迁移一律执行「**先读旧 JSON $\rightarrow$ 合入文档受控块并 SQL 回读核实 $\rightarrow$ 旧 JSON 标记已归档兜底（不物理删文件）**」，确保任何时候零数据丢失、可随时回退。
6. **插件卸载后的终极检验标准**
   - 停用或卸载本插件后，打开 `人脉` 笔记本：没有一段裸露的 JSON 代码、没有重复两遍的待办列表、所有引荐人/同事/组织/会议纪要全部是可点击跳转的原生思源双链、按别名依然能在思源里搜到所有人。

## 六、 分阶段实施路线图（共四期，每期均以 `pnpm e2e:isolated` 真机验收）

### 第一期（P0 · 体验止血与自动上墙闭环 —— 最先做、收益最大）
1. **补充资料去裸 JSON 化**：将 `custom-lvct-person-fields` 升级为人类可读的两层 Markdown 分组列表，自动兼容无损读取存量 JSON 块并在下次保存时平滑转为可读列表。
2. **清理待办双轨重复**：移除 `doc-section.ts` 中重复生成的静态 `## 待办跟进` 块，统一归口至可直接在思源文档打勾双向同步的原生跟进任务块。
3. **人物别名直通思源原生 `alias` 属性**：增删别名自动同步写入人物文档根块 `alias` 属性，打通思源原生 `Ctrl+P` 搜索与 `((` 双链别名补全。
4. **全链路自动增量投影调度器（`DocumentMirrorScheduler`）**：修改基础资料、关系称谓、互动、纪念日、账本后自动按块防抖更新人物文档档案区，彻底告别“必须手动点同步档案到正文”。

### 第二期（P1 · 全双链成网与碎片存储归位人物文档 —— 落实 D-0040 瘦身）
1. **初识溯源、引荐人、亲属与协作项目双链上墙**：并入人物文档 `🪪 身份与关系名片` 受控块，全部输出真实 `((docId '名称'))` 块引用，点亮思源原生反链面板与原生局部图谱。
2. **碎片记忆与约定归位文档**：将 `person-social-preferences`、`person-topics`、`person-scratchpads` 无损收编进人物文档 `💡 记住的事` 分类；将 `person-promises`、`person-itineraries` 收编进原生跟进任务区（带 `[约定]` / `[行程]` 前缀标签），完成自管 JSON 瘦身。

### 第三期（P2 · 组织文档百科化与群体活动纪要联动）
1. **组织文档全要素上墙**：将 `organization-profiles.json`（简称、简介、部门架构树、外链、自定义字段）与「在职成员 + 历史离职成员双链」自动同步至组织文档正文。
2. **群体活动一键建/绑思源纪要文档**：在纪要文档注入参会人脉双链条，并在所有参会人文档的往来记录中反向回链该纪要文档。

### 第四期（P3 · 日记行级精准同步与编辑器协同增强）
1. **Daily Note 行级幂等锚点**：日记互动行携带 `custom-lvct-event-id`，支持插件内就地修改或删除互动时精准同步更新当日日记对应行。
2. **浮动档案条反链转互动 & 手改冲突友好提示**：在人物文档顶部浮动条直接提示未归档的日记/会议提及（一键转互动），并对受控投影块的手工改动提供“刷新 / 保留”防误覆写提示。
